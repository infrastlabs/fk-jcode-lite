## 一、总览

这与同类项目（OpenCode 有多个 fork、Cursor 有社区 patch）不同。

## 七、无持续变体的原因分析

**Jcode 目前没有持续维护的独立变体项目。** 可能原因：

1. **项目年轻**：2026 年初发布，8 月已到 v0.79，上游迭代极快（几乎每天有提交），fork 难以保持独立方向
2. **架构高度内聚**：核心功能（Memory、Swarm、Provider、TUI）紧密耦合在 Rust monorepo 中，难以单独抽取做变体
3. **MIT 开源 + self-dev 模式**：用户可以直接在上游贡献 PR，或用 self-dev 模式让 jcode 自我定制源码，不需要 fork 出去
4. **上游响应快**：Issue 修复通常 1-3 天合入，社区需求能被快速满足，没有积累出"不得不 fork"的压力
5. **无插件市场但有 Skills + MCP**：用户通过 Skills（markdown 指令包）和 MCP 服务器扩展功能，不需要改源码
