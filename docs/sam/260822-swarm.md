# Jcode Swarm 多智能体使用指南

> 基于 v0.79.1 代码与配置分析（2026-08-21）

---

## 一、什么是 Swarm

Swarm 是 Jcode 的多智能体协调系统：并行生成多个代理（worker）执行任务，通过计划（plan）、消息（DM/频道/广播）和任务图（task graph）协调，最后汇总报告。

两种编排模式：

| 模式 | 触发 | 特性 |
|-----------|--------|--------|
| **普通 / light** | `/effort swarm` | 单层扇出：仅根会话可生成，工作代理完成即汇报，不能再生成下一代 |
| **swarm-deep** | `/effort swarm-deep` | 递归生成：管理式分解可创建更深子树，受并发预算约束 |

---

## 二、触发激活方式（3 种）

### 1. 设置推理力度 sentinel

```
/effort swarm          # 浅层 swarm：max 推理 + swarm 编排（light fan-out）
/effort swarm-deep     # 深度 swarm：max 推理 + 实时任务图（deep task graph）
```

swarm/swarm-deep 是 Jcode UI 哨兵值（非提供商推理等级），在 TUI 内映射为 max 推理并注入 swarm 编排指令。系统提示会引导代理：对非平凡任务，使用 `swarm` 工具生成并行代理执行任务并收集报告，而不是单线程自行完成。

### 2. 直接调用 swarm 工具

在会话中指示模型调用 `swarm` 工具（`communicate` 的别名），action 指定操作：

```json
{"action": "spawn", "label": "api reviewer", "prompt": "审查 ...", "model": "gpt-5.5", "effort": "low"}
```

### 3. 编辑路由提示

```
/swarm-prompt
```

打开当前生效的 swarm 路由提示（模型选择策略）进行编辑。

**UI 入口**：`Alt+N` 打开全页实时 Swarm 面板（所有权树、动画状态、详情活动）。

## 三、配置项

### TOML 配置（`~/.jcode/config.toml` 的 `[agents]` 段）

```toml
[agents]
# 生成代理默认模型："inherit"/"coordinator"（继承生成它的会话）或具体模型名
# Env: JCODE_SWARM_MODEL
# swarm_model = "inherit"

# 生成方式：
#   "inline"   - 进程内（无窗口），协调器内显示实时图库视口（默认）
#   "visible"  - 打开有头终端窗口（别名 "headed"）
#   "headless" - 进程内创建，无终端窗口
#   "auto"     - 先尝试 visible，打不开窗口则回退 headless
# 工具每次调用的 spawn_mode 参数可覆盖此设置
# Env: JCODE_SWARM_SPAWN_MODE
swarm_spawn_mode = "inline"

# 单个 swarm 的最大并发工作代理数（RAM 安全预算）
# 0 = 关闭此守卫，仅剩 1000 的绝对硬顶；light 模式使用更小的固定扇出
# Env: JCODE_SWARM_MAX_CONCURRENT_AGENTS
swarm_max_concurrent_agents = 32

# 内联 swarm 图库带最大占用聊天高度百分比（1-90），默认 40
# swarm_gallery_max_pct = 40

# 内联 swarm 条布局：
#   "vertical"   - 每代理一行（会话图标 + 状态 + 任务），超出显示 "+N more"（默认）
#   "horizontal" - 所有代理作为 chip 排成一行
# Env: JCODE_SWARM_STRIP_LAYOUT
# swarm_strip_layout = "vertical"
```

### 顶层配置

```toml
swarm = true                # 功能开关
swarm_panel_focus = "alt+n" # Swarm 面板快捷键
```

### 路由提示覆盖（关键配置）

这个文件本身就是 swarm 的"配置"——路由策略以提示形式传给模型：

- 全局：`~/.jcode/swarm-prompt.md`
- 项目级：`./.jcode/swarm-prompt.md`（优先）

内置默认内容（`crates/jcode-base/src/prompt/swarm_prompt.md`）：

- 默认工作代理模型：Fable 5（Anthropic API 路由 `claude-api:claude-fable-5`）
- 实现类任务：`gpt-5.5` + `effort: "low"`
- 设计/调查/调试/审查/验证：`claude-api:claude-fable-5`
- 上下文提取/批量阅读/总结：`gpt-5.5` + `effort: "none"`
- 路由不可用或不确定时省略 `model`，让工作代理继承协调器模型
- 所有 `spawn` 必须传 `label`（明确拒绝缺失/空白）

## 四、swarm 工具动作全集

### 生成与生命周期

| 动作 | 说明 | 关键参数 |
|---------|-----------|-------------|
| `spawn` | 生成新工作代理 | `label`（必填）、`prompt`/`initial_message`、`model`、`effort`、`spawn_mode` |
| `stop` | 停止代理（自己子树内；外部需 `force=true`） | `to_session`/`target_session`、`force` |
| `wake` | 唤醒代理 | `to_session` |
| `resume` | 唤醒并恢复 | `to_session` |
| `retry` | 重试失败任务 | `task_id` |
| `salvage` | 抢救搁浅任务 | `task_id` |
| `reassign` | 重新分配任务 | `task_id`、`to_session` |
| `replace` | 替换失效代理 | `to_session` |

### 消息通信

| 动作 | 说明 | 关键参数 |
|---------|-----------|-------------|
| `message` | 向单个代理发消息 | `to_session`、`message` |
| `dm` | 私信（别名 `dm_session`/`whisper`） | `to_session`、`message` |
| `broadcast` | 全员广播（别名 `announce`） | `message` |
| `read` | 读取收件箱 | `limit` |
| `share` / `share_append` | 共享/追加上下文 | `key`、`value` |
| `channel` | 频道操作 | `channel` |
| `subscribe_channel` / `unsubscribe_channel` | 订阅/退订频道 | `channel` |
| `channel_members` | 查看频道成员 | `channel` |
| `list_channels` | 列出频道 | - |

### 计划管理

| 动作 | 说明 | 关键参数 |
|---------|-----------|-------------|
| `propose_plan` | 提议计划更新 | `plan_items`、`reason` |
| `approve_plan` | 批准计划 | `task_id`/`node_id` |
| `reject_plan` | 拒绝计划 | `reason` |
| `plan_status` | 查看计划状态 | - |
| `resync_plan` | 重新同步计划 | `task_id` |
| `task_graph` | 任务图操作（构建/查看） | `nodes`、`concurrency_limit` |
| `expand_node` | 展开任务节点 | `node_id`、`nodes` |
| `complete_node` | 完成任务节点 | `node_id`、`artifact` |
| `inject_gap` | 注入缺口（门控评审） | `gate_id`、`nodes` |

### 任务编排

| 动作 | 说明 | 关键参数 |
|---------|-----------|-------------|
| `assign_task` | 分配任务（可自动选下一个可运行任务） | `task_id`、`prefer_spawn` |
| `assign_next` | 自动分配下一个任务 | - |
| `fill_slots` | 填充并发槽位 | `concurrency_limit` |
| `run_plan` | 运行整个计划 | `background`、`retain_agents` |
| `start` / `start_task` | 启动任务 | `task_id` |
| `await_members` | 等待代理完成 | `session_ids`、`mode`（all/any）、`timeout_minutes`、`target_status` |
| `cleanup` | 清理已结束代理 | `retain_agents` |

### 查询与汇报

| 动作 | 说明 | 关键参数 |
|---------|-----------|-------------|
| `list` | 列出代理（`members`/`roster`） | - |
| `list_models` | 查看可用模型/路由 | - |
| `status` | 代理状态快照 | `to_session` |
| `report` | 汇报结果 | `message`、`status`、`validation`、`follow_up`、`tldr` |
| `summary` | 摘要 | `limit`、`to_session` |

## 五、角色与生命周期

### 角色

| 角色 | 职责 |
|---------|---------|
| **协调器（Coordinator）** | 持有共享计划槽位：创建计划、分配范围、审批更新、广播计划更新。仅根会话可担任，且不会在空/过期时被深度后代抢占 |
| **工作区管理者（Worktree Manager）** | 拥有单个 worktree 范围：了解完整计划与范围，负责该范围完成后的集成 |
| **代理（Agent）** | 并行执行任务：接收完整计划+范围指令，发现问题时提议计划更新，通过 DM/频道直接协调 |

### 生命周期状态

`spawned`（已生成，未就绪）→ `ready`（收到计划与范围）→ `running`（执行中）→ `blocked`（阻塞）→ `completed`（完成等待新任务）/ `failed`（不可恢复错误）/ `stopped`（协调器关闭）/ `crashed`（异常退出）

### 所有权与故障处理

- 每个代理通过 `report_back_to_session_id` 挂接到生成者，形成祖先链
- 可以停止自己子树内任何代理；子树外需 `force=true`
- 中间成员离开时，直接子代理被重新挂接到存活的祖父母，回退到协调器，否则成为根
- 会话重命名会重写子代理的 report-back 边
- 死代理任务被回收并汇报协调器；run_plan 遇到凭证失败波次会暂停并展示修复方案

## 七、快速上手

```text
1. 在会话中设置深度模式：
   /effort swarm-deep

2. 给模型一个复杂任务（它会自动用 swarm 工具分解）：
   "重构这个模块，拆成3个独立任务并行执行"

3. 或者直接让模型调用工具：
   "用 swarm spawn 3个代理：一个改API、一个改UI、一个写测试，然后 await_members 等全部完成"

4. 查看进展：
   Alt+N 打开实时 Swarm 面板

5. 需要调整代理模型策略时：
   /swarm-prompt
```

## 八、注意事项

- **标签必填**：`spawn` 必须提供简短 `label`，否则拒绝执行
- **并发预算**：默认 32 并发，完成/停止的代理释放槽位；硬顶 1000
- **深度模式专属**：递归生成只在 `swarm-deep` 根的会话树内允许
- **计划操作门控**：`assign_task`/`approve_plan`/`reject_plan` 等计划操作只允许根协调器（共享计划只有一个）
- **长消息**：超过折叠阈值的 message/report 需要 `tldr`，在收件人 UI 折叠显示
- **模型覆盖**：`model`/`effort` 参数优先级高于 `agents.swarm_model` 配置
- **记忆作用域**：swarm 工作代理能看到生成它的会话的项目记忆（非隔离存储）
- **记忆侧车（memory sidecar）**：独立的 LLM 精度判定器，专职处理记忆相关性判定与提取，随主会话并行运行（区别于 swarm 工作代理本身）
